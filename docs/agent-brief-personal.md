# 子任务说明：参考用户个人应用重写

先读 `docs/agent-brief-own.md`（桌面模板工具的全部规则，照做），再读本文件。本文件只补充「参考个人应用重写」这类任务的额外规则。

## 背景

- 用户以前自己做过一批应用，界面不满意，要按工具箱标准重做后上架。参考源码在 `ref-src/<仓库名>/`（只读，**不要修改、不要提交、不要复制 git 历史**）。
- 用户拍板：以参考仓库的**功能和业务逻辑为主**（它们是完整实现过的），界面用工具箱模板重做；可以移植参考仓库里用户自己写的代码。
- 统一署名「篝火出品」，许可证 MIT。

## 必须去掉的东西（逐项检查，最终报告里逐项说明）

1. 激活码、授权服务器、试用期、付费套餐、代理分销、自动更新到个人服务器。
2. 写死的密钥、token、密码、AppID / AppSecret、服务器地址或 IP、个人域名、本机路径、微信号、手机号、收款码、个人或公司品牌名、真实门店或客户数据。**最终报告里不要写出这些值本身**。
3. 用到大模型或图像模型的：一律在设置页由用户填接口地址、密钥、模型名（兼容 OpenAI 接口格式，用 kit 的 `chat()` 与设置），不内置任何密钥。
4. 自动操作第三方平台的工具：保留功能，但会动钱、批量或高频的操作（自动改价、自动提交上架、批量发送）**默认关闭**，由用户在设置里手动打开，并在 README 顶部写「风险与免责」一节。

## 交付

- 编号、仓库名、名称、一句话简介已写在 `catalog/tools.json`，直接 `node scripts/new-tool.mjs <编号>`。
- 参考仓库里的测试、样例数据可以改写后放进 `src/tool` 的测试和 `samples/`（样例必须是虚构数据，标明「示例」）。
- 不要建仓库、不要推送、不要发版；做到 `node scripts/check-tools.mjs <编号> --build` 全过、截图检查过为止。
- 最终报告追加一节「对照参考仓库」：保留了哪些功能、去掉了哪些（对应上面 1～4）、没能移植的功能和原因。
