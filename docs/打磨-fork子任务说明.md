# 打磨子任务说明（fork 工具）

fork 工具的界面是上游写的。这次打磨的目标有三条：

- 应用区里看到的截图和文字**只用中文**。
- 我们能改的地方（启动包、部署文件、说明卡、README、上架文案）全部中文化，并且写准确。
- 不同工具的截图和说明卡不要长成一个样。

汇总仓库：`/Users/wumin/Project/small-project`。工具目录是 `tools/<slug>`，每个工具是 campfire-code 组织下 fork 上游得来的独立仓库。

## 先读

- `docs/术语表.md`：中文规则和允许保留的原文。
- `docs/打磨-子任务说明.md`：自研工具的说明。其中的设计规则、文案要求、提交方式同样适用。
- `docs/进度交接.md`：「复用流程」一节写了 mirror / launcher / docker 各是什么。
- 本工具的 `README.md`、`campfire/` 目录（如果有）、`docs/screenshot.html`（说明卡源文件，如果有）。

## 按类型做

| 类型 | 截图怎么来 | 要改的文字 |
|---|---|---|
| **A 上游有中文界面** | 能在本机跑起来的，切到中文后截真实界面。跑不起来的（要下载几百 MB、要账号），用上游 README 或文档里的**中文界面图**，放进说明卡。也没有中文图的，说明卡里用 HTML 画出该软件主要界面的示意（只写中文），并标注「示意图」 | README 写清楚怎样切到中文 |
| **B 有中文包，但默认语言不是中文** | 我们自己出包的，把默认语言改成中文后截图 | 同上 |
| **C 上游没有中文** | 汉化我们出包时会带上的界面文字，改源码里的字符串，或加中文语言包并设为默认；之后截图 | 汉化要完整，不要只改首页 |
| **E 没有界面**（服务、MCP、油猴脚本） | 重做中文说明卡 `docs/screenshot.html` 并渲染成 `docs/screenshot.png`。内容是这个工具真实的使用画面：例如企业微信群里机器人回答的对话气泡、AI 客户端里调用工具的过程、淘宝页面上脚本工具栏的示意。不要写成一页文字说明 | 说明卡里不能有英文 |

## 通用要求

1. **截图规格**：保存为 `docs/screenshot.png`，宽度 2080 像素（按 1040 宽、2 倍像素比渲染），亮色。截完用 Read 看图，不能有英文、报错，也不能有任何个人信息。
2. **README**：
   - 把给用户看的英文说明改成中文；上游原文的致谢、许可证段落保留。
   - 删掉引用上游英文截图的地方，或改用中文截图。
   - `README_en.md`、`README-EN.md` 这类英文文档不能进我们的发布包。检查发布流程或打包脚本会不会带上它们，会带上就排除。
3. **上架文案**：重写 `catalog/copy/<编号>.json`。保持原有字段，另外加 `scene: { title, body }`；全中文，只写真实功能。
4. **中文自查**：在我们改过的文件里搜英文。例如 `grep -nP '[A-Za-z]{3,}'` 配合人工判断，命令、环境变量名、文件名可以保留。
5. **版本和提交**：
   - **launcher / docker / desktop / userscript 类**，改了界面或出包内容的：按原来的版本规则加一个小号。例如 `v2.1.1-campfire.1` 改成 `v2.1.1-campfire.2`，版本号写在哪里，看仓库里原来怎么写。
   - **mirror 类**：只改 README、说明卡、截图，不升版本。
   - 提交命令：`git -c user.name=wuniba1997 -c user.email=wuniba1997@gmail.com commit`，提交信息结尾写 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。
   - 不推送、不打标签、不发版。这些由总控统一做。
6. **不许做**：
   - 不向上游推送任何东西。
   - 不改上游的功能逻辑。
   - 不写明文密钥。
   - 不提交汇总仓库。
   - 上游要求「禁止商用」或没有许可证的代码，不要复制。
