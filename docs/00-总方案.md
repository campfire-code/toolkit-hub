## 三、统一基础设施

1. **汇总仓库**（就是本目录，推到组织下名为 `toolkit-hub`）：
   - `catalog/tools.json` 是全部工具的唯一清单，记录每个工具的状态、仓库、版本、下载地址；
   - `.github/workflows/` 放**复用出包工作流**；
   - `scripts/` 放生成目录、汇总 Release、生成上架材料的脚本；
   - `README.md` 是自动生成的总目录。
2. **模板仓库 `toolkit-template`**：
   - 技术栈：Tauri 2 + React + TypeScript + Vite，界面全中文；
   - 自带：通用布局、文件拖入、批量任务进度、结果导出、大模型设置页；
   - 可选 `sidecar/`：Python + PyInstaller 打成内置程序，工具需要 Python 库（抠图、语音识别、OCR 等）时启用；
   - 自带文件：MIT LICENSE、THIRD_PARTY_LICENSES、`tool.json`（名称、分类、图标、平台）、中文 README 骨架。
3. **出包流程**：
   - 工具仓库打 `v*` 标签后，调用 `toolkit-hub` 里的复用工作流；
   - 三个平台并行构建：Windows（NSIS 安装包 `.exe`）、macOS Apple 芯片、macOS Intel（`.dmg`，临时签名）；
   - 构建前先在对应平台跑测试，产物自动上传到 Release。
   - fork 项目的出包方式各不相同，按上游实际情况选一种：
     - 上游已有安装包的，直接沿用；
     - Python 网页界面类（Streamlit、Gradio）做「便携包 + 一键启动脚本」；
     - 服务端类（企微机器人等）出 Docker 镜像和 `docker compose` 一键部署文件；
     - 浏览器插件类出 `.zip`。
4. **汇总**：脚本按组织 topic `campfire-toolkit` 拉取全部仓库和最新 Release，刷新 `catalog/tools.json` 与 README 总目录，并生成 `catalog/store-listing.json`（应用区上架材料：分类、名称、简介、截图、版本、更新说明、仓库地址、下载链接，价格留空）。

## 四、阶段与验收

### 阶段 0：基础设施（不依赖组织名的部分先做）
- 0.1 汇总仓库骨架、总目录、后做清单 ✅ 本次完成
- 0.2 本机安装 Rust 与 Tauri 构建环境；建模板仓库并在本机打出 `.app` / `.dmg`
- 0.3 写复用出包工作流
- 0.4 推送 `toolkit-hub`、`toolkit-template`，用模板生成一个样例工具，打标签跑通三平台出包
- 0.5 汇总脚本：生成总目录与上架材料

**验收**：
- 在样例仓库执行 `git tag v0.1.0 && git push --tags`，Actions 三个平台的构建全部为绿色；
- Release 里有 `.exe` 和两个 `.dmg`；
- 本机下载 `.dmg`，按 README 步骤安装后能启动；
- `node scripts/build-index.mjs` 生成的 README 里出现该样例，且下载链接可以打开。

### 每个工具的验收标准（阶段 1、2 通用，全部可执行）
1. 仓库在组织下公开，有 topic `campfire-toolkit` 和中文 README。README 包含：能做什么、截图、下载、首次打开步骤、使用说明、许可证、上游致谢。另有 LICENSE 和 THIRD_PARTY_LICENSES。
2. 打 `v*` 标签后 Actions 全绿，Release 里有该工具形态对应的产物：桌面工具是 `.exe` 加两个 `.dmg`；服务端是镜像加 compose 文件；插件是 `.zip`。
3. 核心逻辑有自动测试，在 Windows 和 macOS 两个平台的 Actions 里都要通过。自研工具用 `pnpm test`；带 Python 内置程序的再加 `pytest`。
4. 仓库里有 `samples/` 示例输入，以及 README 里的「验收用例」。在本机用安装好的 `.dmg` 按用例操作，输出与 README 写的一致。需要平台账号或密钥的工具（企微、公众号、各电商开放平台、大模型），用模拟数据跑通，真实账号联调列入待联调清单。
5. 在 `catalog/tools.json` 里把该工具的 `status` 改为 `released`，并填上 `repo`、`version`、`release`。

## 五、挑战清单

| 挑战 | 影响 | 对策 |
|---|---|---|
| 成员未接受邀请 | 他们暂时看不到私有内容（仓库都公开，不影响） | 无需处理 |
| macOS 不签名 | 用户首次打开被拦截 | 临时签名 + README 图文步骤；以后要改再买开发者账号 |
| SignPath 审核需要时间 | 期间 Windows 包会弹 SmartScreen | 先发未签名包，审核通过后重新出包 |
| Python 工具体积大 | 抠图、语音识别模型几百 MB | 模型不打进安装包，首次使用时下载并显示进度；默认用 CPU 可跑的小模型 |
| 需要显卡的工具（c12 声音克隆、c16 去水印、c02 影视解说部分功能） | 无法双击即用 | 交付「便携包 + 环境检查脚本」，README 写清显卡要求；不承诺无显卡可用 |
| Release 单个文件上限 2 GB | 带模型的整合包可能超限 | 拆分下载或首次运行下载模型 |
| 平台接口要资质（抖店、Shopee、亚马逊、TikTok、企微、公众号） | 无法用真实账号验收 | 用模拟数据和接口录制回放测试；真实联调需要你或运营提供测试账号，列入待联调清单 |
| fork 项目上游变化快 | 中文化补丁冲突 | 改动尽量放在独立文件（中文语言包、启动器、打包脚本），README 记录对应的上游版本 |
| 高风险的 19 个（个微 Hook/群发、视频下载、闲鱼自动化等） | 封号、平台规则、侵权 | 只开源不上架；README 顶部写风险与免责，默认关闭批量与高频操作 |
| 96 个工具工作量大 | 一次会话做不完 | 进度以 `catalog/tools.json` 为准，每批结束更新状态，下个会话从清单接着做 |
