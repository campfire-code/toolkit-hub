每个工具怎么交付

一个工具 = 一个独立 GitHub 仓库。打版本标签后自动出 Windows / macOS 安装包，汇总仓库（就是 small-project 这个目录）生成总目录，再到 campfire 后台建一件应用区商品，交付内容填仓库地址和下载链接。campfire 应用区现有的「资源链接」交付方式已经够用，不需要改 campfire。

GitHub 上没有能直接复用的成熟项目，只能从零做。正规做法需要申请平台开放平台的服务商资质；不走开放平台就只能模拟商家后台操作，有封号风险。清单里把它们拆成了风险更低的「上架数据包生成」类工具。

微信类工具大多有风险

个人微信的 Hook 或协议方案正在被微信打击：Gewechat 被官方点名后停止维护，WeChatFerry 已归档，PyWxDump 和「留痕」已删库。推荐只做走企业微信、公众号官方接口的工具，以及不碰微信客户端的内容类工具。

许可证决定能不能拿来改

MIT、Apache、BSD 许可证的项目可以随意改了再开源；GPL / AGPL 可以用，但我们这个工具也要用同样的协议开源；非商用协议或没有许可证的项目只能参考思路，代码要自己写（例如 MediaCrawler、RedInk）。

需要显卡的工具不适合普通运营

声音克隆、数字人、AI 绘图要 NVIDIA 显卡和几 GB 的模型，双击安装很难跑起来，默认放在「后做」或「不做」。只用 CPU 加云端大模型接口的工具最容易做成双击即用。
